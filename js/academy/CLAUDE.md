Notes for Claude, loaded automatically when working in this folder. The project-wide rules are in the
root `CLAUDE.md`. Keep invariants for this area here; update them when one changes.

## Files
- `academy-sw.js` + `academy.webmanifest` + `images/academy/` — the Academy as an installable, offline app (served by server.js too)
- `academy.html` + `js/academy/academy.js` (edition loading, shared filter, mode switching) + `js/academy/modes.js` (the nine modes) — 🎓 Triventurex Academy

## Effect types and related notes
- **Triventurex Academy**: `academy.html` (served at `/academy`, PUBLIC root route in server.js) must work from disk: it loads ONLY `js/shared/*`, `js/academy/*` and `game_editions/editions.js` (checked by test/html-structure.test.js), and each edition's `config.js` + `questions.js` as plain scripts. One edition at a time — switching reloads the page (`?edition=`), so no CONFIG reset is needed. New mode = one `registerMode({...})` in js/academy/modes.js; round-building logic goes in js/shared/academy.js with a test. Question cards in every mode share ONE look (css/academy.css `.ac-qcard` group: white inside, `--green` top accent, gold for answer sides) — reuse it, don't restyle per mode. Printed cards have fixed mm sizes (double-sided 90 × 62 mm, fold-over 90 × 124 mm folded in the middle). Every edition must give each mode content (test/academy.test.js)
- **Academy on phones** (≤ 720px — `isPhone()` in js/academy/academy.js matches the CSS `@media (max-width: 720px)`): one-row top bar; the mode tabs scroll (active tab centred, edges fade); modes with `phone: false` (Print cards, Review) leave the tabs for a **More** sheet; *Choose what to learn* opens as a sheet from the bottom (`.ac-filter-body`, Show N questions button) — a filter change redraws the mode WITHOUT closing it (`showMode` closes sheets only when the mode changes); Flashcards: phones always one card (`.ac-flash-one`, swipe or ←/→); a computer shows a set of 4 / 8 / 12 cards (*cards in a set*, saved in `triventurex_academy_flash_size`, `CONFIG.ACADEMY.flash`). The set only changes when you pick another size or cross the phone width — NEVER from resizing or the text size: those only change `--cols` on `.ac-flash-grid` (`flashColumns()` in js/shared/academy.js: cards ≥ `cardWidth` × text size, at most `maxCols`), via a ResizeObserver on `#ac-main` and the `textsizechange` event, without redrawing (turned cards stay turned). Flex-wrap grid, short last row centred; reviewer bits (Mark as wrong, Marked only) are `.ac-desk` — hidden on phones except in Review. `.ac-phone-only` / `.ac-desk` toggle by width; hovers sit in `@media (hover: hover)`; the page height is `100dvh` (test/html-structure.test.js checks it)
- **Academy as an app** (install + offline): `academy-sw.js` at the project root, registered by academy.js with **scope `./academy`** — it controls ONLY the Academy page (never the game / phone / TV pages; keep it that way). Only over https or localhost (not from disk, not `http://<lan-ip>`). Install saves `ACADEMY_FILES` (every script + stylesheet academy.html loads — **a new script in academy.html must be added there**, test/academy-offline.test.js checks it), every edition's config.js + questions.js (ids parsed from editions.js) and the emoji SVGs (`TX_ICON_DATA.emoji` via importScripts). Code/questions: network first (4 s wait, then the saved copy) so content updates arrive; pictures: cache first. Place photos: saved when shown, or all at once with More → *Save photos for offline* (the page writes to the same cache — `ACADEMY_CACHE` must match in both files). Changing the caching? Raise the version in `ACADEMY_CACHE` (both files). More also offers *Install the Academy* (`beforeinstallprompt` — Chrome / Edge / Android only; it NEVER fires on an iPhone, whatever the browser, all are WebKit) or, on iPhone / iPad, an *Add to your home screen* button that opens the steps for the browser in use (`iosBrowser(ua, touchPoints)` + `homeScreenSteps(browser)` in js/shared/academy.js: Safari / Chrome (CriOS) / Firefox (FxiOS) / Edge (EdgiOS) / other → open in Safari, with *Copy the link*). The iPhone item shows even without offline support (http://<lan-ip>) — Add to Home Screen works there, only offline doesn't. Headless Chrome fires `beforeinstallprompt` even with an iPhone user agent — clear `_installPrompt` to test the iPhone path. server.js serves `/academy-sw.js` and `/academy.webmanifest`
- **Tags + About this answer**: the filter has tag chips (`#ac-tags`, `ac.tags`, every chosen tag must match; a tag clicked on an Explore / Review item adds it — `addFilterTag`). Explore / Review show the full check info under the answer (`checkDetailsHtml`). Learning cards (Flashcards, Quiz, True or false, the *Look at these again* list) get a small round info button (`_infoBtn` in modes.js, `data-q-info`) ONLY once the answer is shown — it never gives the answer away; Speed and Match have none. It is absolute in the card's corner (cards keep their size; meta lines get right padding). Inside a flashcard (itself a `<button>`) it is a `span role=button`; a document CAPTURE click/Enter handler (`_initQuestionInfo` in academy.js) opens `#ac-info` (*About this answer*: `questionInfoHtml`) and stops the event, so the card never turns. `#ac-info` = a centred box on a computer, a bottom sheet on a phone; `closeSheets()` / Esc / the backdrop close it and focus returns to the button
- **Text size** in the Academy: top bar A− / A+ (`.ac-desk`), phones: *Text size* in More (`applyTextSize(currentTextSize())` after drawing it). Cards that grow: `#ac-list, .ac-flash-grid, .ac-panel, .ac-match-grid, .ac-places, .ac-summary, .ac-missed` — never tabs, filter, the bar above the cards or printed cards (see *Text size* in js/shared/CLAUDE.md)
